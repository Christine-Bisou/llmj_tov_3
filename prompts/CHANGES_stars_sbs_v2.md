# Второй промт (звёзды + SbS): что изменено и зачем

Цель — поднять `acc_draw_05` с 0.68 до ≥0.75.

## Что показывает GS

`tov_gs_v5.xlsx`, 431 строка. После маппинга `winner` → `answer_source_1/2`:

| Вердикт | Кол-во | Доля |
|---|---|---|
| model_1 | 178 | 41.3% |
| model_2 | 198 | 45.9% |
| draw (вкл. both_bad) | 55 | 12.8% |

Ничья — **1 случай из 8**. Промт v1 при этом писал «**НЕ БОЙСЯ СТАВИТЬ tie!**» и давал два широких основания для неё. Это прямой конфликт с распределением золота.

## Как устроена метрика (и что из этого следует)

В `acc_draw_05` ничья стоит ровно 0.5 балла, правильный решительный вердикт — 1.0, ошибочный — 0. Решать выгоднее, чем ничьить, при точности выше 50% — то есть почти всегда.

При этом склейка прямого и обратного прохода частично спасает ничьи:

```sql
WHEN direct = reversed_normalized THEN direct
WHEN direct IN ('draw','tie')      THEN reversed_normalized
WHEN reversed_normalized = 'draw'  THEN direct
ELSE 'draw'
```

Ничья в одном проходе не фатальна, если второй проход решил. **Фатально противоречие**: прямой говорит `model_1`, обратный — `model_2` → `draw` → 0.5. Значит главный источник потерь — не робость, а **позиционная нестабильность**. Отсюда приоритет правок.

Арифметика цели: при доле ничьих ~12% на решительных парах и ~35% попадании в GS-ничьи нужна точность на решительных парах около **0.80**, чтобы выйти на 0.75.

## Правки, по убыванию ожидаемого эффекта

### 1. Разрыв связи между оценкой и позицией (главное)

* Жёсткий порядок шагов: профиль запроса → границы ПР → **оценка ответа 1 в изоляции** → **оценка ответа 2 в изоляции** → overall → лестница. Раньше промт не запрещал сравнивать во время выставления звёзд, и оценка второго ответа зависела от первого — это и порождало флипы.
* Прямой запрет: «Оценивай так, будто второго ответа не существует», «оценка „4, потому что лучше соседнего“ недопустима».
* Прямое указание, что порядок случаен и вердикт обязан отзеркалиться при перестановке.

### 2. Вердикт стал функцией от чисел, а не от впечатления

Новая **лестница из 10 ступеней** (Блок 6): критичный тон → единица по аспекту → встречные единицы → overall → сумма трёх аспектов → приоритетный аспект → второй по приоритету → качественные различители → tie. Модель обязана назвать номер сработавшей ступени в `reasoning`.

Ступень 5 (сумма аспектов при равном overall) вытаскивает из ничьих большой пласт пар: 4+4+3 и 3+4+3 дают одинаковый overall, но разное качество.

### 3. Таблица приоритета аспектов по типу запроса

В v1 приоритет аспектов не был задан вообще — модель каждый раз решала заново, что важнее, и на обратном проходе могла решить иначе. Теперь шесть типов запроса (A–F) с фиксированным порядком: например, фактово-справочный → Ясность > Коннект > Живость, болталка → Коннект > Живость > Ясность. Это и ступень лестницы, и правило корректировки overall.

### 4. Рубрики стали детерминированными

Таблицы звёзд из инструкции сохранены целиком, но:
* добавлено **правило наслоения**: два и более признака одного уровня → минус ступень (в инструкции это было «можно снизить», то есть на усмотрение);
* добавлены опорные маркеры для каждого аспекта — какие именно поля из первого этапа читать;
* сформулировано «средний ответ — это 3, а не 4» против компрессии оценок в 4–5;
* добавлено «если один ответ по аспекту заметно лучше, оценки ОБЯЗАНЫ различаться» — прямо против ничьих на равных звёздах.

### 5. Overall стал воспроизводимым

Было: «округляем не по правилам математики, а по общему впечатлению» — источник нестабильности. Стало: половина вверх + **одна** именованная корректировка вниз (если приоритетный для запроса аспект на 1–2 ★) + сверка с портретом. Примеры подсчётов из инструкции сохранены и пересчитаны по новому правилу.

### 6. Калибровка ничьей

Вместо «не бойся ставить tie» — базовая частота 1 из 8 и требование показать, на какой ступени лестница не разрешилась. Оба основания для ничьей из v1 сохранены, но сужены: «симметричное качество» теперь ступень 9 (все три аспекта совпали и различители тоже), «оба хуже по-разному» — ступень 3 (у обоих есть 1 ★ по разным аспектам и по разнонаправленным причинам).

### 7. Запрет на посторонние основания

Явно: нельзя выбирать победителя за длину, подробность, оформление, достоверность и полезность. В комментариях GS видно, что это регулярный источник расхождений с золотом.

# ⚠️ Два бага в пайплайне

**1. `verdict: "skip"` в формате выхода.** Блок 4 v1 разрешал `model_1 / model_2 / tie`, а блок 5 в формате JSON писал `[model_1 / model_2 / tie / skip]`. В GS строк со скипом нет, а SQL не обрабатывает `skip` отдельно — он проваливается в `ELSE 'draw'`, то есть каждый скип это гарантированные 0.5. В v2 `skip` убран из промта совсем.

**2. `score` должен быть целым.** Метрика читает оценки так:

```sql
CAST(Yson::LookupInt64(Yson::Lookup(Yson::Lookup($yson_node, $model), $aspect), 'score') AS Double) ?? 0.0
```

`LookupInt64` вернёт null на `4.5`, на `"4"` и на `"4-5"` — и `?? 0.0` молча превратит это в ноль. Средние по аспектам поедут вниз, а понять по таблице это невозможно. В v2 требование «целое число 1–5» вынесено в жёсткие требования Блока 0 и продублировано в формате выхода. Если хочешь подстраховаться на стороне SQL:

```sql
$get_score = ($n, $model, $aspect) -> {
    $node = Yson::Lookup(Yson::Lookup($n, $model), $aspect);
    RETURN Yson::ConvertToDouble(Yson::Lookup($node, 'score')) ?? 0.0;
};
```

`ConvertToDouble` съест и int, и double; строку — нет, её пришлось бы кастовать отдельно.

# Обновление по поинтвайз-GS

Разобрал `Разметка пойнтвайз.xlsx` — листы `gs` + 8 асессорских. После склейки: **277 оценённых ответов, 139 пар с вердиктом**.

## Факт 1. Общая оценка идёт за Ясностью, а не за средним

Проверил, чем предсказывается `pointwise`:

| Правило | Точное совпадение |
|---|---|
| среднее арифметическое, округление половина вверх | 0.51 |
| floor(среднее) | 0.56 |
| min из трёх аспектов | 0.59 |
| медиана | 0.54 |
| **оценка за Ясность** | **0.79** |
| **Ясность, −1 если И Живость, И Коннект ниже неё на 2+** | **0.81** (в пределах ±1 балла — 0.996) |

Асессоры формально считают среднее, фактически — ставят общую по Ясности. Видно и в остатках: `pointwise − Ясность` равен нулю в 218 случаях из 277, −1 в 48, +1 всего в 8. Блок 5 переписан под это правило, среднее оставлено как самопроверка.

## Факт 2. Реальное распределение оценок

| Аспект | 1★ | 2★ | 3★ | 4★ | 5★ |
|---|---|---|---|---|---|
| Ясность | 1% | 11% | 38% | 43% | 7% |
| Живость | 2% | 20% | 38% | 24% | 16% |
| Коннект | 4% | 31% | 23% | 9% | 33% |
| Общая | 3% | 16% | 39% | 35% | 7% |

Отсюда две поправки к промту. Первая: моё прежнее «средний ответ — это 3, а не 4» неверно для Ясности — там 4 встречается чаще 3, а 5 действительно редкость. Вторая, более интересная: **Коннект двухполюсный** — 5★ (33%) и 2★ (31%), а 4★ самая редкая оценка во всей разметке (9%). Модель либо попала в тон, либо нет; промежуточных состояний асессоры почти не размечают. Добавил это в новый раздел 4.1 вместе с таблицей.

## Факт 3. Лестница подтвердилась, и главный шаг — не тот, что казался

| Ситуация | n | Что делают асессоры |
|---|---|---|
| Общие оценки различаются | 89 | вердикт по ним — 87/89 (**98%**) |
| Общие равны, наборы аспектов разные | 29 | ничья лишь 4 (**14%**); сумма аспектов угадывает победителя 20/25 (**80%**) |
| Все три аспекта совпали | 20 | ничья 13 (65%), решительный вердикт 7 |

Прогнал лестницу на человеческих оценках аспектов — то есть померил потолок самой решающей логики, если бы модель оценивала аспекты как асессор:

| Конфигурация | acc_draw_05 |
|---|---|
| среднее + округление, без шага «сумма аспектов» (это v1) | 0.791 |
| среднее + округление, с шагом «сумма аспектов» | 0.939 |
| привязка к Ясности, без шага «сумма аспектов» | 0.849 |
| **привязка к Ясности + шаг «сумма аспектов» (это v2)** | **0.942** |

Отсюда честный вывод: **для SbS главный выигрыш даёт не привязка к Ясности, а ступень 5** — тай-брейк по сумме аспектов при равной общей оценке (+0.15). Привязка к Ясности важна для поинтвайза (0.51 → 0.81) и добавляет к SbS ещё немного. И главное: 0.94 — это потолок агрегации. Значит вся оставшаяся ошибка сидит **в оценках по аспектам**, а не в правилах вывода вердикта. Дальше улучшать надо рубрики, а не лестницу.

## Факт 4. Три калибровочных примера в промте (новый Блок 7)

Взял реальные случаи с эталонными оценками:

1. **«номер оператора мтс»** — А 4/2/3 → 3, Б 5/5/5 → 5. Оба фактически верны, у А аккуратный список. Разрыв в две звезды создаёт только наличие собеседника: у Б «в зависимости от того, откуда вы звоните», совет от себя, предложение помощи.
2. **«что будет если подтягиваться каждый день»** — А 2/2/2 → 2, Б 5/5/5 → 5. Оба со структурой и подзаголовками. Пример специально показывает, что `##`-разделы сами по себе оценку не роняют: А написан о теме («может иметь как положительные, так и негативные последствия в зависимости от индивидуальных особенностей организма»), Б — пользователю («что произойдет с вашим телом»).
3. **«среда Вильсона-Блера»** — А 2/1/2 → 1, Б 2/2/2 → 2, вердикт Б. Два почти одинаковых справочных ответа всё равно разводятся и получают решительный вердикт. Заодно показывает низ шкалы: 1★ по живости — рабочая оценка для мёртвого текста.
