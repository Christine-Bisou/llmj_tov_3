# Что изменено в промте v2 и зачем

Оптимизация под то, как устроен GS: **если галочка в золоте стоит — маркер точно есть; если не стоит — не факт, что его нет.**
Значит, FN (пропуск) — настоящая ошибка, а FP — часто ложная тревога метрики. Поэтому целимся в **recall → 100** и в accuracy, а precision читаем как нижнюю границу.

Базовые метрики (Gemini, промт v1):

| Маркер | F1 | Precision | Recall | Диагноз |
|---|---|---|---|---|
| Субъектность | 0.91 | 0.92 | 0.90 | ок, не трогаем |
| Роботность | 0.87 | 0.84 | 0.90 | ок, не трогаем |
| Недочёты во вступлении | 0.85 | 0.86 | 0.85 | ок, не трогаем |
| Недочёты в проактивности | 0.57 | 0.40 | 0.95 | recall есть, режем FP |
| Попадание в тон | 0.36 | 0.27 | 0.54 | и недобор, и перебор |
| Словесные пряности | 0.44 | 0.32 | 0.72 | перебор |
| Гиперэмо | 0.33 | 1.00 | 0.20 | **сильный недобор** |
| Тяжёлое восприятие | 0.28 | 0.80 | 0.17 | **сильный недобор** |
| Ошибки языка | 0.21 | 0.16 | 0.31 | и недобор, и выдуманные ошибки |

## Главный структурный рычаг: принудительные сканы (новый Блок 3)

Раньше был один `linguistic_scan`. Теперь шесть обязательных сканов, результат которых пишется в JSON **до** решения по маркерам: интент/границы ПР, тон-триггеры, духота (6 механических правил), гиперэмо (чек-лист + подсчёты), шаблоны, лингвистика (по предложениям), обращения + блок ПА.

Модель не может поставить `false`, не перечислив, что именно она искала. Это прямой рычаг на recall у гиперэмо / духоты / ошибок языка — они проваливались именно потому, что решение принималось «на глаз» одним взглядом.

## Новый Блок 0 — калибровка

Явная таблица политик: какие маркеры «чувствительные» (при сомнении → true), какие «строгие» (нужен подтверждающий гейт). Плюс аксиома «нет цитаты — нет маркера», которая держит precision там, где модель склонна фантазировать.

## Новый Блок 4 — кросс-проверки

11 правил на противоречия: шаблон не может быть эмпатией; эмпатия на нейтральный запрос → гиперэмо; `tone_match` без цитаты-триггера снимается; `critical_tone` тянет за собой `boundaries_violation`; если субъектности нет и обращений в теле нет → почти наверняка духота (Паттерн Б).

## По маркерам

**`stuffy_bureaucratic` (recall 0.17).** Взят твой вариант с Паттерном А/Б (он давал лучшее качество) и дополнен всем, что было в v1 и в инструкции, но выпало: отглагольные заголовки, нанизывание падежей, длина предложений, безличные инфинитивы в инструкциях, неуместные смайлики, непоследовательность и «бредовые фразы», духота на болталочный запрос. Сверху — **6 автоматических правил**, которые проверяются механически (нет «вы/ты» в теле; 2+ `##`-раздела без переходов; ≥2 канцелярских слова-триггера; отглагольный заголовок; списочная простыня на болталку; инфинитивы в инструкции). Любое из них само по себе даёт true.

**`over_emotional` (recall 0.20).** Главная причина недобора — модель ждала «сериальной драмы». Добавлено явное «порог низкий» + чек-лист из 15 сигналов, разделённых на сильные (1 достаточно) и слабые (нужно 2), с числовыми порогами по эмодзи, восклицаниям и вопросам. Добавлены кейсы, которых в v1 не было: коуч-стайл, уменьшительно-ласкательные, наигранная теплота, «я»-высказывания о себе. Сохранён антипример (тёплое вступление при нормальном теле = `bad_intro`, не гиперэмо), чтобы не поехала точность.

**`language_errors` (P 0.16 / R 0.31 — плохо в обе стороны).** Скан теперь идёт по предложениям с фиксированным списком из 12 проверок. Добавлено **правило подтверждения**: кандидат засчитывается, только если названы тип ошибки и правильный вариант, иначе «отклонено» — это режет выдуманные ошибки. Расширены списки паронимов, плеоназмов, нарушений управления и несочетаемости. Добавлен явный список «что НЕ ошибка» (орфография, пунктуация, канцелярит, разговорные конструкции, ошибки в креативе, цитаты пользователя).

**`tone_match` (P 0.27 / R 0.54).** Добавлен жёсткий гейт: нет тон-триггера в запросе → false всегда; нужны обе цитаты (триггер из запроса + зеркало из ответа). Для recall — развёрнутый список из 8 типов тон-триггеров, включая те, что модель раньше не считывала (просьба о стиле, детская речь, троллинг, профжаргон, обрывочная манера).

**`humor_metaphors` (P 0.32).** Добавлен явный список «что НЕ считается»: термины, сленг (→ tone_match), речевые клише, эмодзи, бодрые глаголы. Список «что считается» оставлен широким, чтобы не потерять recall 0.72.

**`bad_proactivity` (P 0.40 / R 0.95).** Добавлен гейт: нет блока ПА → false; нужна цитата негатива именно из ПА. Начальные связки «Если хотите / Если уточните» подтверждены как не-шаблон. Recall при этом держится кросс-правилом №2 в Блоке 4.

**`empathy`.** Добавлен триггер перекрёстной проверки (эмпатия на неэмоциональный запрос → гиперэмо) и явное «дежурные формулы — это шаблон».

## Что убрано

- Угроза «дисквалификации» в конце. Она не даёт калибровки, а провоцирует перестраховочные срабатывания. Заменена на конкретное напоминание о типичном недоборе + требовании цитаты.
- Дубли и противоречия между разделами (например, духота была описана в двух местах по-разному).

# ⚠️ Баг в YQL-скрипте

Две строки маппинга смотрят в ключи, которых в предикте нет, — метрика по ним всегда выйдет нулевой:

```sql
<| marker: "tov_plus_clarity",      g: ..., p: $get_p($p, "logical_anchors") |>   -- ясности больше нет, строку можно удалить
<| marker: "tov_tone_unacceptable", g: ..., p: $get_p($p, "unacceptable")    |>   -- промт отдаёт ключ critical_tone
```

Правка:

```sql
<| marker: "tov_tone_unacceptable", g: $get_g($g, "tov_tone_unacceptable"), p: $get_p($p, "critical_tone") |>
```

и строку с `tov_plus_clarity` просто выкинуть.
